2 · Domain Core

Referral lifecycle + immutable event stream

Partner- and channel-agnostic. Knows nothing about Zerodha or Wati specifically — those are plugins around it. This is the part that never changes when you swap a partner or a messaging tool.

3 · Rule Engine — two separate cascades

Compliance constraints vs configuration values

These look alike but merge in opposite directions. Keeping them separate is the crux of the design. Rules also carry a domain (advertising-compliance · referral-behaviour · message-delivery) because they fire at different moments.

🛡️ Compliance cascade tighten-only · most-restrictive wins

A lower layer may only add restrictions, never loosen a higher one.
1 Regulator (NSE/SEBI, IRDAI, RBI) ▾
2 Category (Brokers…) ▾
3 Partner (Zerodha AP rules) ▾
4 Sub-broker (PIFS's own limits)
Effective policy = union of all restrictions on the path.

⚙️ Config cascade override · nearest wins

Values (reward text, creative, channel). The closest layer's value wins. (ADR-022)
1 Central defaults ▾
2 Global (admin) ▾
3 User / tenant
Effective value = the most specific override set.
